# Telegram-бот «Головний Інженер» — ТЗ для MVP/Prod

## Роль
Ти — Senior Full-Stack Developer + DevOps + Architect. Потрібно спроєктувати, реалізувати та запустити в продакшн Telegram-бота «Головний Інженер» для публічного користування.

## 1. Мета продукту
Telegram-бот, який:

* приймає текст, фото, PDF/DOCX, голосові повідомлення
* працює як інженер-консультант
* відповідає чітко, по суті, на основі документації
* накопичує та використовує базу технічних знань
* весь інтерфейс і відповіді — українською мовою

## 2. Мова та стиль
* Мова: тільки українська
* Коротко, технічно, без “води”
* Якщо даних недостатньо — бот ставить уточнюючі питання
* Нічого не вигадує, якщо цього нема в документації

## 3. UX / Поведінка бота (без кнопок)
### /start
Бот надсилає тільки текст:

```
🧠 Я — ШІ бот «Головний Інженер».

Я допомагаю з промисловим, енергетичним та електротехнічним обладнанням.

📥 Надішли:
• марку та модель обладнання
• фото шильдика або обладнання
• інструкцію / регламент (PDF, DOCX)
• голосове повідомлення з питанням

🧾 Якщо документація вже є — просто задай питання.

Напиши:
«Що вміє цей бот» — щоб побачити можливості.
```

### Команда (єдина)
Фраза, а не кнопка:

```
Що вміє цей бот
```

### Відповідь:
```
🔧 Що я вмію:

• допомагаю з першим запуском обладнання
• пояснюю налаштування та режими роботи
• розбираю аварійні помилки та коди
• перевіряю сумісність з іншим обладнанням
• аналізую інструкції та регламенти
• працюю з фото, PDF, DOCX та голосом

📚 База знань постійно поповнюється.
```

## 4. Типи вхідних даних (обов’язково)
### 4.1 Текст
* бренд / модель
* питання у вільній формі

### 4.2 Фото
* обладнання
* шильдик
* плата / підключення

Бот намагається визначити бренд/модель та, якщо не впевнений, просить уточнення.

### 4.3 PDF / DOCX
* інструкції
* регламенти
* технічні описи

Файли витягуються, структуризуються, індексуються у векторну БД та прив’язуються до бренду/моделі.

### 4.4 Голосові повідомлення
* автоматична транскрипція
* аналіз як текстового запиту
* відповідь — текстом українською

## 5. Основні сценарії
### Сценарій 1: Є документація
1. Користувач задає питання
2. Бот знаходить релевантні документи
3. Відповідає у форматі:

```
✅ Коротко по суті

🔧 Покроково:
1.
2.
3.

⚠️ Важливо / що не робити

📌 Джерело: інструкція, розділ / сторінка
```

### Сценарій 2: Документації немає
Бот відповідає:

```
У базі немає документації для цієї моделі.

Будь ласка, надішли:
• PDF/DOCX інструкцію
або
• точну назву бренду та моделі
```

## 6. Обробка документів (RAG)
* PDF/DOCX → текст
* розбиття на чанки
* індексація (pgvector або Qdrant)
* пошук за змістом, а не лише за назвою
* відповіді формуються виключно з джерел

## 7. Адмін-режим (мінімальний)
(через Telegram, без UI)

Команди:
* `/admin`
* `/stats` — користувачі, документи, запити
* `/docs бренд модель`
* `/reindex`
* `/ban /unban`

## 8. Безпека
* перевірка типів файлів
* обмеження розміру
* rate-limit
* логування без персональних даних
* стійкість до спаму

## 9. Технології (рекомендовано)
* Backend: Python + aiogram
* DB: PostgreSQL
* Vector: pgvector або Qdrant
* Queue: Redis + Celery/RQ
* Files: S3 / MinIO
* Deploy: Docker + VPS
* SSL + Nginx

## 10. Архітектура
* bot-service
* worker-service (PDF, фото, голос)
* postgres
* vector-db
* redis
* object storage

## 11. Acceptance Criteria
Проєкт вважається готовим, якщо:
* бот приймає текст / фото / PDF / голос
* дає точні технічні відповіді українською
* не вигадує дані
* стабільно працює після перезапуску
* база знань розширюється без ручного втручання
